# Theming

Themes change the palette while preserving component meaning. A component's color role, variant, hierarchy, and interaction behavior must remain recognizable in every theme and in both light and dark modes.

Shared component variants, defaults, glyph treatment, and interaction states are defined in <a href="./?path=/docs/design-system-appearance--docs" target="_top" style={{ textDecoration: 'underline' }}>Appearance</a>.

## Modes

Light and dark modes reverse the primary surface and content ranges. Components use theme roles and documented shade rules rather than assuming a fixed light or dark foreground.

Use the `ThemeModeToggle` assembly for the light/dark control. It reads the current mode from the theme context; connect `onToggle` to the application's mode state.

## Named Themes

Named themes provide different visual identities through shared palette roles. They must not require component-specific branches or change what a state means.

Use the `ThemeSelect` assembly as the theme dropdown. Pass the selected theme through `value` and apply selections through `onChange`; `mode` determines the palette previews shown in its options.

## Colors

Theme colors can use any of the available <a href="./?path=/docs/design-system-colors--docs#palettes" target="_top" style={{ textDecoration: 'underline' }}><strong>pallettes</strong></a>.


### Design System Color

- **Neutral** — default usage.
- **Primary** — enhanced usage, no clear guidelines.
- **Secondary** — enhanced usage, no clear guidelines.
- **Tertiary** — enhanced usage, no clear guidelines.

### Semantic Colors

- **Glitch** — status / error state
- **Hazard** — warning / caution state
- **Secured** — success / confirmed state
- **Intel** — informational / neutral-highlight state

## Elevation

Elevation describes separation between surfaces independently from component colors and appearance variants. `raised` is used by persistent panels and toolbars, `floating` by transient widgets and notices, and `overlay` by popups, menus, dropdowns, and dialogs. Direction is selected by the renderer so side and bottom panels cast outward shadows.

Global layer policies explicitly pair a z-index with an elevation level. A higher z-index does not imply a stronger shadow: tooltips stack above dialogs but use the lighter floating elevation.

`Theme.elevation()` returns platform-neutral metrics for surfaces without a global stacking role. Web renderers consume generated `--elevation-<level>-<direction>-shadow` or `-filter` variables; mobile renderers translate the same metrics with `resolveElevationStyle()`.

Globally stacked surfaces use their layer as one policy: web consumes `--layer-<name>-z-index` with `--layer-<name>-<direction>-shadow`, while mobile uses `resolveLayerStyle()`. Do not select a global layer's z-index and elevation independently. Literal shadows are reserved for intrinsic effects such as focus rings, glows, and inset geometry, not surface depth.

### Global layers

These rows come directly from `Theme.layers`, grouped by their elevation and ordered by z-index within each group. Elevations do not have a universal z-index: `raised` surfaces use their renderer's layout stacking, and a tooltip's floating elevation can still stack above an overlay dialog.

<table>
    <caption>Combined global layer and elevation policies</caption>
    <thead>
        <tr>
            <th scope="col">Elevation</th>
            <th scope="col">Layer</th>
            <th scope="col">Z-index</th>
        </tr>
    </thead>
    <tbody>
        {elevationLevelOptions.flatMap((level) => {
            const layers = Object.entries(Theme.layers)
                .filter(([, policy]) => policy.elevation === level)
                .sort(([, first], [, second]) => first.zIndex - second.zIndex);
            if (layers.length === 0) {
                return [
                    <tr key={level}>
                        <td><code>{level}</code></td>
                        <td>No global layer</td>
                        <td>Renderer-owned</td>
                    </tr>,
                ];
            }
            return layers.map(([layer, policy]) => (
                <tr key={layer}>
                    <td><code>{level}</code></td>
                    <td><code>{layer}</code></td>
                    <td>{policy.zIndex}</td>
                </tr>
            ));
        })}
    </tbody>
</table>
