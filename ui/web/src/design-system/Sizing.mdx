# Sizing

The shared component size scale is `xs`, `sm`, `md`, and `lg`. Components that expose `size` must support the complete scale on both platforms. The standard default is `sm` unless a component documents a reason to use another size.

The height and padding columns are baselines for input-like controls. Components with distinct geometry, such as buttons, chips, toggles, and shaped panels, document their own internal padding, gaps, stroke widths, and shape depth while following the same progression. `size` must not add external margin or layout spacing around arbitrary child content.

## Layout Boundary

- Callers own external margin, positioning, and composition spacing.
- Containers do not impose content padding unless padding is part of their documented contract.
- Surface geometry and appearance do not imply content padding.
- Full-width content such as selectable rows may extend to a shaped container's clipped edge.

Use spacing tokens for layout spacing. Do not overload component `size` as a general-purpose padding prop.

Document component-specific sizing contracts in the component's own documentation.
