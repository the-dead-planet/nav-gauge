# Colors

Colors use perceptually ordered shades from `50` through `900`. Shade `500` defines each palette's identity; the surrounding shades preserve its hue while moving toward light and dark endpoints. Neutral palettes additionally limit chroma so they remain suitable for surfaces and text.

## Shade roles

Default text and icons use `900` in light mode and `100` in dark mode. Main application surfaces use the inverse: `100` in light mode and `900` in dark mode.

Shade `50` is an optional brightest tint for maximum-light details and subtle fills. It is intentionally not a default semantic color; use `100` for normal dark-mode text so text and application backgrounds remain symmetric at `100` and `900`.

These defaults do not guarantee accessibility. Verify contrast when combining chromatic foregrounds and backgrounds or rendering small text.

<h2 id="contrast-shades">Contrast shades</h2>

A contrast shade is foreground text or icon color selected from the same palette for legibility against a filled background. The theme compares the background shade's OKLCH lightness with the shared contrast threshold and selects shade `100` for dark backgrounds or `900` for light backgrounds. Components recalculate it when an interaction changes the background shade; do not assume one contrast shade for an entire palette.

## Variants

Disabled state always wins. Hover and focus temporarily use their interaction shade, while pressed and persistent active use the stronger active shade. Interactive states use `highlightColor ?? color`; default and disabled states use `color`. Focus also has a visible focus indicator. Interact with the default and active examples to inspect their transient states.

Inset controls use no border in any state. Their internal shading alone creates the appearance of a control dented into its surface.

Owned active content uses `highlightContentShade` when supplied, otherwise the variant's existing contrast rule. Components must not recolor arbitrary children or apply whole-control opacity when they own surface and content channels.

## Active glow

`activeGlow` is an optional enhancement to the existing color, border, and content state cues. It uses `highlightColor`, never replaces the required state treatment, and is removed when a component is disabled.
